intent 상태머신

의도는 소유자·상태를 가진 1급 노드. frontier에서 열리고, 워커가 집어 돌리고, 결과에 따라 닫힌다.

%%{init: {'theme':'dark','themeVariables':{'fontFamily':'IBM Plex Sans KR, sans-serif','fontSize':'13px','lineColor':'#7d8590'}}}%%
stateDiagram-v2
  [*] --> open: 플래너 생성
  open --> running: 워커 claim
  running --> done: 결론 (yields fact/finding)
  running --> blocked: 모델·툴 실패
  running --> exhausted: 시간 T 소진 (부분결과 보존)
  running --> stopped: 플래너 중단 (목표달성·중복)
  blocked --> open: 재투입
  done --> [*]
  exhausted --> [*]
  stopped --> [*]

claim은 원자적 전이여야 한다 — 두 워커가 같은 의도를 집지 않도록 open→running을 조건부 쓰기(한 번에 하나만 성공)로. 단일 프로세스라 프로세스 락 또는 Neo4j 조건부 갱신이면 충분.

핵심 3가지

추론 병렬 / 실행 직렬워커 N개는 동시에 생각하되, 모든 execute_action은 단일 레인으로 모아 하나씩. 재생 결정론 보존.
step_id = 전역 실행 순서{round}.{seq}의 seq가 모든 워커를 아우르는 단일 증가값 = replay_script의 선형 순서. 이미 깔아둔 토대.
공유는 그래프로만워커끼리 직접 값 전달 없음. 발견은 fact로 그래프에 쌓고, 플래너·다른 워커는 그래프를 읽어 조율.
