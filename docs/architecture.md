# 아키텍처 개요

## 루프 (0~8단계)

```
0 초기화    VM C: 베이스라인 리셋·플래그 배치·발판(foothold)만 전달
1 공격자 턴  VM A: 자율 정찰·공격 (execute_action 단일 통로로 리플레이 대본 기록)
            종료 3조건: 플래그 / 시간 T 소진 / 막다른 길
2 상태 보존  VM C: '공격 후' 스냅샷 저장 + 정답 타임라인 기록 (방어자 비공개)
3 관측      VM B: 감사로그·Falco·상태 수집 → 필터 → 상황 보고서
4 판단·패치  VM B: LLM 트리아지 → 패치 세트 1개 atomic 적용 (헬스체크)
5 검증      VM C: 리플레이(pre/post) + 상태검증 → 판정
            (pre 실패 시 post 생략, 상태검증으로)
6 채점      VM C: 정답 대조 TP/FP/FN·MTTD·플래그·가용성, JSON Lines 로깅
7 반복      종료 안 되면 라운드++ → 1단계로 (VM B 리셋 안 함, 패치 누적)
8 에피소드   종료조건 충족 시 결과 기록 → 0단계 clean 리셋 (여러 에피소드 반복)
```

## 턴 예산
- 공수 모두 라운드당 최대 시간 T. 소진 시 턴 종료(중립 타임아웃).
- 방어자는 라운드당 패치 1회 = 여러 공격 패치를 묶은 세트를 atomic 적용.
  시간 내 못 하면 0회. 세트 크기 상한 없음(관측 범위로 자연 제한).

## 검증 (5단계) — pre/post 분기
```
STEP0  패치 후 상태 '임시 스냅샷' 저장
STEP1  '공격 후'(패치 전) 스냅샷으로 revert
STEP2  대본 재생(pre) → pre 결과
         pre 실패(재현 불가) → post 생략 → 상태검증으로
STEP3  '패치 후' 임시 스냅샷으로 복귀
STEP4  대본 재생(post) → post 결과
판정:  pre성공+post실패 = 진짜 차단 / pre성공+post성공 = 가짜 패치
       pre실패 → 상태검증(vulnerable false=차단 / true=미차단 / 불가=검증불능)
```

## 리플레이 실패 3중 그물
1. 예방 — 의존성 기반 리플레이(inputs/produces) + 구조화 출력(-o json) + 정규화
2. 보강 — 상태 검증 병행(공격 재현 없이 취약 조건 확인, VM A 데이터 무관)
3. 최후 — 보수적 판정(방어 안 됨 가정) + 투명 집계(검증불능 비율 보고)

## 성공/실패 판정 (전부 VM C god-view)
- 공격 성공: 플래그 도달 사실 — 값 기반(값 대조, 랜덤이라 위조 불가) / 상태 기반(감사로그)
- 방어 실효: 리플레이 pre/post 재현
- 탐지 정확도: 방어자 주장 vs 정답 타임라인 → TP/FP/FN
- 방어자는 추측(탐지), 심판은 사실로 판정.

## 환경 구축 (6단계)
```
0 인프라      VM 3개 + 3망(공격/관리/모델) + k3s
1 Goat 배포   레벨1 시작
2 자체 서비스  nginx + Flask + PostgreSQL + 더미 트래픽 (레벨2 전환)
3 킬체인      (B) Goat 취약점 레시피를 자체 스택에 이식, 흔한 실수처럼 은폐
4 플래그+MITRE 상태/값 기반 플래그, ATT&CK for Containers 매핑
5 관측+리셋    Falco + 감사정책 + VMware 스냅샷 자동화
```
각 단계마다 수동 검증 (자동 루프 전에 사람이 킬체인을 끝까지 뚫어봐야 함).

## 네트워크 3망
- 공격망 (Host-only, 격리): VM A ↔ VM B 공격 경로
- 관리망 (Host-only): VM C ↔ A/B 제어·보고 (VM C는 공격망에 안 붙음)
- 모델망 (NAT + 방화벽): DGX IP:포트만 허용, 그 외 인터넷 차단
