# 향후 연구 및 발전 방향 (Future Work)

**프로젝트**: LLM 기반 Kubernetes 자동 공격-방어 공진화 시스템 (공수 공진화)
**문서 목적**: 현재 프로토타입이 **검증한 것**과, 그로부터 확장 가능한 **발전 방향**을 정리한다. 캡스톤 논문의 "향후 연구" 절 및 발표 자료의 근거 문서.
**작성 기준일**: 2026-10-17

---

## 0. 요약 (TL;DR)

- 현재 킬체인 시스템(①②③④ + 심은 FLAG)은 **"AI 추론 기반 공수 진행이 정상적으로 측정되는가"를 검증하는 통제된 벤치마크**다. 정답(ground truth)이 있는 환경에서 측정 장치를 먼저 검증하는, 올바른 부트스트랩 단계.
- 발전 방향은 네 갈래(A 타깃 분리 / B 자율 추론 / C 자산 기반 판정 / D 환경 일반화)이며, **전부 구현 가능**하다. 다만 난이도 티어가 다르고, 서로 맞물려 서로의 빈틈을 메운다.
- 유일한 하드 제약은 **"실 운영계에 대한 완전 자율 파괴 행동"**이며, 이는 디지털 트윈 + 사람 승인 게이트로 설계가 흡수한다.

---

## 1. 현재 시스템의 위치 — 무엇을 검증했나

현재 프로토타입은 "정해진 킬체인"으로 보이지만, 실제로 **정해진 것은 공격자의 '뇌'가 아니다.** 시스템을 움직이는 요소를 분해하면:

| 요소 | 내용 | 현재 상태 |
|---|---|---|
| **A. 공격자 LLM의 판단(뇌)** | 킬체인을 모른 채 평범한 셸 명령을 치고, 하네스가 발판 파드(frontend) 안에서 `kubectl exec`로 실행 (`exec_mode`) | **이미 자율** — 순서를 사람이 가르치지 않음 |
| **B. 환경 셋업(판)** | 내부 위키에 크레덴셜, admin-sa에 과권한, NetworkPolicy 부재, postgres에 FLAG를 **의도적으로 배치** | 심어져 있음 (통제 변수) |
| **C. 채점(심판의 정답지)** | VM C god-view가 ①③=Falco, ②=audit log, ④=FLAG 값 매칭으로 확인 | 심어져 있음 (ground truth) |

**핵심**: 방어 LLM 또한 공격 정보를 0으로 받고 관측(audit·Falco)만으로 **자력 추론**한다. 즉 공·수 양측의 추론 자율성은 이미 확보되어 있고, "정해진" 것은 **B(판)와 C(정답지)**뿐이다.

**이 단계가 검증하는 것**: 관측→추론→행동→채점 루프(측정 장치)가 정답이 있는 환경에서 올바르게 동작하는가. 라벨된 데이터로 탐지기를 먼저 검증하는 것과 같은 순서이며, 미지의 환경으로 나아가기 전 반드시 선행되어야 하는 부트스트랩이다.

---

## 2. 관통하는 두 개의 설계 축

발전의 전제는, 현재 프로토타입이 한 덩어리로 묶어 둔 두 가지를 **분리**하는 것이다.

### 2.1 두뇌(하네스 루프) ↔ 시나리오(환경 + 성공 판정 기준)

- **두뇌** = 관측→추론→행동→채점 루프. 본질적으로 환경 무관(agnostic).
- **시나리오** = 환경마다 달라지는 것: (a) 관측 어댑터(로그 소스), (b) 행동 인터페이스, (c) **성공 오라클(무엇을 성공으로 볼 것인가)**.
- 이 셋만 어댑터로 분리하면 두뇌는 그대로 재사용된다.
- **코드 토대**: `defender/patcher.py`의 `ClusterClient`, `defender/state_query.py`의 `ClusterReader` 프로토콜 — 적용/조회 I/O가 이미 추상화되어 주입식(injection)으로 설계됨. k8s(`KubectlCluster`)는 그 구현체 하나일 뿐.

### 2.2 실험 모드 ↔ 운영 모드

| | 실험 모드 (현재) | 운영 모드 (목표) |
|---|---|---|
| 대상 | 심은 테스트 타깃 | 실제 자산 |
| 타임라인 | 에피소드 반복 (i.i.d.) | 단일 연속 타임라인 |
| 정답 | 심은 FLAG (ground truth) | 사용자 지정 중요자산 |
| 리셋 | 에피소드 경계 baseline 원복 | **불가** (남의 운영계를 롤백 못 함) |
| 행동 승인 | 자동 | **사람 승인 게이트** |

> 같은 두뇌가 두 모드로 동작한다. 운영 모드는 리셋이 불가하므로 자동으로 **누적·단일 타임라인**(보류 중인 `skip_revert`의 실전판)이 된다.

## 3. 발전 방향 (로드맵)

### 방향 A — 타깃 환경의 독립 분리

- **현재**: VM-B = 타깃 k3s(ShopFlow) + 방어 하네스 + Falco 동거.
- **목표**: 타깃을 독립 VM/자산으로 분리하고, 방어 하네스는 **고정 서비스**로서 외부 타깃에 attach.
- **난이도**: 🟢 **엔지니어링** (확실히 가능, 코드 수정 거의 0).
- **코드 근거**:
  - `KubectlCluster`는 `kubeconfig` 주입으로 동작 → 노드 위에 있을 필요 없이 API 엔드포인트만 가리키면 됨. `TargetConfig.kubeconfig` 주석: *"VM C god-view 조회용"* (원격 kubeconfig 패턴이 이미 존재).
  - 유일한 결합점은 Observer의 로그 2종(audit·Falco). 그런데 `ObservabilityConfig` 주석: *"관리망으로 마운트/동기 전제"* — 설계가 처음부터 원격 로그를 가정.
  - 로그 동기 파이프라인은 이미 VM C god-view가 수행 중(`vmc-sync-falco.sh`, `vmc-sync-audit.sh`, systemd 유닛) → 방어 VM용으로 재활용.
- **필요 작업**: config 3줄(원격 kubeconfig / 동기된 audit 경로 / 동기된 falco 경로), 방어 VM→클러스터 API(6443) 네트워크 경로, 로그 전송 지연의 라운드 경계 flush 보장.
- **귀결**: **운영 모드의 선결 조건.** 방어자가 임의의 외부 자산을 다루려면 타깃이 변수가 되어야 하므로, 타깃과 한 호스트에 묶일 수 없다.

### 방향 B — 유도 없는 자율 취약점·공격경로 추론

- **현재**: B(판)와 C(정답지)가 심어진 상태. A(공격 뇌)는 이미 자율.
- **목표**: **B를 연다** — 구멍·목표를 미리 배치하지 않고 임의 환경을 투입, 공격자가 스스로 취약점과 경로를 발견.
- **난이도**: 🔴 **연구 프론티어** — 성공은 이분법이 아니라 **등급제**. 모델·정찰도구 성능에 비례해 좋아지는 축.
- **"뇌를 바꾸는 게 아니라 시나리오를 여는 작업"**: 공격 LLM의 사고방식은 그대로 두고, 미리 깔아 둔 판(B)과 정답지(C)만 치운다.
- **한계 요인** (2026 초 공개 연구 기준 — 원데이/체인 자동 익스플로잇 LLM 에이전트):
  - **(a) 행동·정찰 인터페이스의 풍부함** — 현재는 발판 셸 하나. 미지 환경을 뚫으려면 포트스캔·서비스 식별·취약점 스캐너 등을 LLM 손에 쥐어줘야 한다.
  - **(b) 공격면의 조합 폭발** — 심은 4단계가 아니라 수백 서비스·설정의 미로. 길 잃기 쉬움.
  - **(c) 성공 판정 공백** — FLAG가 없으니 "진짜 성공 vs 환각/거짓 보고"를 가릴 길이 없다. → **방향 C가 이 공백을 메운다.**

### 방향 C — 사용자 지정 중요자산 기반 판정

- **현재**: 심은 FLAG가 성공 오라클.
- **목표**: 사용자가 **중요자산(crown jewel)을 직접 지정** → "공격자가 이 자산에 도달/장악했는가"가 새로운 성공 기준.
- **난이도**: 🟡 **엔지니어링 + 일부 연구**(도달성 분석).
- **방향 B와 한 세트인 이유**: B만 하면 채점이 불능(c)이 되는데, C가 심은 FLAG를 대신하는 **새 정답지**를 공급한다.
- **부수 효과**: 탐색 공간 축소. 사용자가 장비별 리스크를 판단해 범위를 좁히므로(일부 위험은 수용), B의 조합 폭발(b)도 완화된다. 실제 리스크 관리 실무(crown jewel 분석, 위험 수용)와도 정합.
- **기술 수단**: "발판 Y에서 자산 X로 도달 가능한가"는 공격경로 분석(BloodHound류 reachability) + LLM 익스플로잇으로 부분 자동화되는, 잘 정의된 문제.

### 방향 D — 다양한 환경/아키텍처 일반화

- **목표**: k8s 외 백엔드(일반 서버, 클라우드 구조 등)로 확장.
- **난이도**: 🟡 **설계 + 구현** (연구가 아닌 엔지니어링).
- **수단**: 2.1의 두뇌/시나리오 분리를 **명시적 환경 어댑터 / 시나리오 스펙** 계층으로 승격. `ClusterClient`/`ClusterReader` 프로토콜이 그 패턴의 싹.
- **병목**: 환경별 관측 배선과 성공 오라클 정의(방향 C와 연결).

## 4. 제약과 안전 (반드시 명시)

**실 운영계에 대한 "완전 자율" 파괴적 행동 — 공격이든 패치든 — 은 책임상 완전 자율이 될 수 없다.** LLM이 승인 없이 프로덕션에 `kubectl delete`·RBAC 변경·NetworkPolicy를 적용하는 것은 폭발 반경·인가·안전 문제다.

**흡수 설계** (둘 중 하나, 또는 병행):
1. **디지털 트윈/복제본**에 대해 공격·패치를 실행하고, 검증된 패치만 사람이 실계에 반영.
2. **dry-run + 승인 게이트 + 스코프 자격증명 + 롤백**을 강제하는 human-in-the-loop.

**이미 확보된 뼈대** (`defender/patcher.py`):
- **dry-run 원자 관문** — 세트 전체를 `--dry-run=server`로 먼저 검증, 하나라도 실패 시 통째 미적용.
- **healthcheck** — 패치 후 앱 네임스페이스 Deployment ready 확인(과잉 차단 감지).
- **POST-only** — 패치는 적용만, 스스로 되돌리지 않음(누적 전제).

→ 운영 모드는 여기에 **"승인 게이트" 한 겹**을 얹는 자연스러운 확장이다.

## 5. 의존 관계 및 제안 우선순위

```
A (타깃 분리) ──── 운영 모드의 선결 조건
                      │
C (자산 판정) ◀──한 세트──▶ B (자율 추론)
   │                         (B만으론 채점 불능 → C가 오라클 공급)
   └── 성공 오라클 교체가 D의 전제이기도 함
                      │
D (환경 일반화) ──── 2.1 어댑터 계층에 의존
```

**제안 순서**:
1. **A** — 타깃 분리(엔지니어링, 저위험). 운영 모드로 가는 길을 연다.
2. **C** — 성공 오라클을 심은 FLAG → 사용자 지정 자산으로 교체.
3. **B** — 판을 점진적으로 연다(정찰 도구 인터페이스부터). C가 채점을 받쳐주는 범위 안에서.
4. **D** — 두뇌/시나리오 어댑터 계층을 정식화해 백엔드 확장.

## 6. 평가 지표의 진화

| 구분 | 실험 모드 (현재) | 운영 모드 (목표) |
|---|---|---|
| 탐지 품질 | confusion matrix (정밀도/재현율, 서브기법 정규화) | 자산 도달 탐지 여부 |
| 시간 | MTTD (평균 탐지 소요 라운드) | 침해~차단 소요 시간 |
| 진행도 | stage reached (도달 킬체인 단계) | 지정 자산까지의 경로 진행도 |
| 방어 효과 | 패치 후 재침투 차단 | 패치 후 자산 도달 차단율 |
| 부작용 | healthcheck 실패(과잉 차단) | 과잉 차단율 + 사람 개입 빈도 |

## 7. 한눈에 보기

| 방향 | 현재 | 목표 | 난이도 | 선결/짝 |
|---|---|---|---|---|
| **A 타깃 분리** | 타깃·방어 동거(VM-B) | 타깃 독립, 방어는 attach | 🟢 엔지니어링 | 운영 모드의 선결 |
| **B 자율 추론** | 판·정답지 심어짐 | 구멍 미배치, 자력 발견 | 🔴 연구(등급제) | C와 한 세트 |
| **C 자산 판정** | 심은 FLAG | 사용자 지정 자산 도달 | 🟡 엔지니어링+연구 | B의 채점 공백을 메움 |
| **D 환경 일반화** | k8s 전용 | 임의 아키텍처 | 🟡 설계+구현 | 2.1 어댑터 의존 |

**결론**: 네 방향 모두 구현 가능하다. 유일하게 등급제·게이트가 붙는 지점은 "실 프로덕션을 사람 개입 없이 알아서 털고 패치한다"는 극단뿐이며, 그 극단은 트윈/승인 게이트로 설계가 흡수한다.
